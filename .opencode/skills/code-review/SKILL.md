# Code Review

Стандарт качества для frkn.org. Применяй при ревью своих изменений, PR и перед коммитом.

## Процесс

### 1. Определи, что ревьюить

**По умолчанию (нет аргументов):** дифф текущей ветки относительно её базы:
```powershell
git diff main...HEAD        # feature-ветка
git diff epic/site-dev...HEAD  # ветка от эпика
```

**Аргументы:** `staged` / `unstaged` / commit hash / branch name / PR url — как обычно.

### 2. Собери контекст
- Прочитай полные файлы, не только diff
- Релевантный домен-док из `docs/domains/` — страница описана там как ожидается?

### 3. Что искать (специфика статик-сайта)

- **Битые пути** — абсолютные `/Images/...`, `/styles.css`, `/scripts/...`; регистр (`Images` с большой). Каждый `src`/`href` должен существовать на диске.
- **Локали в синхроне** — изменил секцию в `index.html` → то же в `en/index.html` (и `fa/` если реальная). Структура должна совпадать.
- **Cache-bust** — изменил `styles.css` или `scripts/*.js` → бампнут `?v=N` во всех HTML (все локали!). См. skill `cache-bust`.
- **Partials** — страница подключает `containers.js` и имеет `#logo-container`/`#footer-container`? Без них шапка/футер пустые.
- **API-вызовы** — новый fetch → должен быть в `docs/domains/api-integration.md` (обновить на docs sync).
- **Кириллица** — в файле не «РљРѕРґ» (признак записи через PowerShell).
- **Мёртвый код** — удалил элемент → удалил его CSS/JS (preload, классы, обработчики).
- **Inline-стили** — ок для одноразовых подгонок; повторяющееся — в styles.css.

### 4. Перед тем как флажить
- Будь уверен. Не уверен — проверь через explore agent.
- Не выдумывай гипотетики. Edge case — только с realistic-сценарием.
- Не нуди про стиль.

### 5. Формат вывода
- Баг — прямо, почему это баг, как воспроизвести.
- Severity соразмерно. Тон: matter-of-fact, без лести.

## Критерии качества

### Общие
- Имена осмысленные; kebab-case для файлов, camelCase в JS
- Отступы 2 пробела, LF, UTF-8 (`.editorconfig`)
- Комментарии — только для неочевидного
- DRY: дублирующиеся блоки между локалями — норма проекта (отдельные HTML), НЕ предлагать «выделить в компонент»

### Безопасность
- Никаких хардкодов секретов/ключей/токенов
- Пользовательский ввод (email, промокод, ключи) — валидация на клиенте + понятные ошибки
- `onclick="window.open(...)"` — только на доверенные домены (t.me, status.frkn.org и т.п.)

### Верификация
- UI-изменение → скриншоты desktop+mobile по локалям (skill `verify` / agent `visual-check`)
- Перед коммитом: docker build не сломан, `/health` → ok

## Red flags (блокируют коммит)
- Хардкод секретов
- Ссылка на несуществующий файл (404)
- ru/en рассинхрон по структуре
- Файл с битой кодировкой
- Изменён общий ассет без бампа `?v=`
