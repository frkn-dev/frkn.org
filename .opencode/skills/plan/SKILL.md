# Plan — декомпозиция задачи

Загружай при старте любой нетривиальной задачи, ДО написания кода. Выход — подзадачи в todowrite (+ `PLAN.md`, если задача большая).

## Вход

- Запрос пользователя (что сделать).
- Находки исследования: какие страницы/ассеты затрагиваются.

Если исследования не было — сначала исследуй (AGENTS.md, Навигация). План без исследования — гадание.

## Правила декомпозиции

- **Подзадача = один коммит.** Не укладывается в атомарный коммит — режь дальше.
- **Ветка от `epic/site-dev`** (или от `main`, если эпик не заведён). Фича = 1-3 дня, не укладываешься — режь.
- **Локали — одна подзадача.** Меняешь секцию — меняешь во всех локалях, где она реальна (ru/en, fa точечно), в том же коммите.
- **Порядок:** общие ассеты (styles.css, scripts/, container/) → страницы. Сначала то, без чего остальное сломается.
- У каждой подзадачи — конкретные файлы. «Поправить главную» — не подзадача.

## Формат PLAN.md (для больших задач)

```markdown
# PLAN

## <ветка> — <суть одной строкой>

**Цель:** что изменится для пользователя.
**Критерий приёмки:** скриншоты ок, /health ok, локали в синхроне, ...

### 1. <подзадача>
- [ ] действие — файлы: `index.html`, `en/index.html`

## Бэклог (не в этой ветке)
- отрезанное, с пометкой почему
```

Для мелких задач PLAN.md не нужен — достаточно todowrite.

## Q&A — уточняющие вопросы

После черновика — уточняющие вопросы через tool `question`.

**Сколько:** 0 (всё очевидно) — до ~10.

**О чём спрашивать (по важности):**
1. **Дизайн/UX** — как именно должно выглядеть? Есть варианты — предложи со скриншотами-представлением, плюсами/минусами.
2. **Scope** — что входит, что в бэклог? Все ли локали затрагиваем?
3. **Edge cases** — мобайл, RTL, пустые состояния (API недоступен) — покрываем или потом?
4. **Приоритеты** — что сначала?

**Формат:** короткий вопрос + 2-4 варианта (question tool с `options`).

Не навязывай вопросы ради вопросов.

## Обновление по ходу

- Сделал подзадачу → `[x]` + коммит. Сразу, не пачкой.
- План изменился → перепиши, не продолжай молча по старому.
