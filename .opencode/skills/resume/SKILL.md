# Resume — продолжить после сбоя

Когда сессия прервалась (контекст обнулился, пользователь сказал «продолжай» / «resume» / «где остановился»).

## Процесс

### 0. Прочитай чат — понять, откуда продолжать

Перечитай историю диалога. Найди:
- **Какая задача** — фича/баг, ветка
- **Где остановился** — писал код? скриншотил? ждал ответа?
- **Последнее указание** пользователя

Если история обрезана — переходи к шагу 1 (восстановление через git).

### 1. Контекст через git

```powershell
git branch --show-current
git status --short
git log --oneline -5
```

Пойми: на какой ветке (обычно `epic/site-dev` или `feature/...`), какие коммиты есть, есть ли незакоммиченное.

### 2. Где остановился?

- `PLAN.md` (если есть) — последняя `[ ]` без `[x]`.
- Незакоммиченные изменения в `git status` — допиши/закоммить.
- Сверь: задачи `[x]` должны соответствовать коммитам в логе.

### 3. Продолжай

- **НЕ переспрашивай** «где я остановился?» или «что дальше?»
- Продолжай автоматически с точки прерывания.
- Если менял UI и не проверял — прогони docker + скриншоты (см. skill `verify`).

## Чек-лист

- [ ] Чат прочитан — задача и точка остановки понятны
- [ ] Ветка определена; если на `main`/`epic` с незакоммиченным — `git stash -u`, feature-ветка, `git stash pop`
- [ ] `git status` + `git log -5` — контекст понят
- [ ] Незакоммиченное разобрано (дописать/закоммитить)
- [ ] Работа продолжена без вопросов
