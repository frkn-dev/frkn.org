# page-audit — аудит качества страниц

Загружай для проверки сайта на пропуски и проблемы. Тестов нет — это наша замена coverage-аудиту.

## Процесс

### 1. Explore-агенты параллельно по доменам
По каждому домену из `docs/domains/` (site-structure, frontend, payments, subscription-app, blog, install-setup) запусти agent `explore`:

```
Проверь страницы домена <domain>:
- Каждый src/href на локальный файл существует (ассеты, partials, /Images/)
- Каждая внутренняя ссылка (href="/...") ведёт на существующую страницу
- Страница подключает analytics.js, containers.js и имеет #logo-container/#footer-container
- Версии cache-bust (?v=N) одного ассета одинаковы во всех страницах
- ru/en версии структурно синхронны (те же секции)
- fa-страница: реальная или редирект-заглушка — соответствует ли ожиданию
Верни список проблем по severity (HIGH/MEDIUM/LOW).
```

### 2. Структурные проблемы (сам)
- Мёртвый CSS в `styles.css` — классы без совпадений в HTML (осторожно: partials тоже используют)
- Неиспользуемые файлы в `Images/`
- Дубли ассетов (например `dopamine/scripts/` vs `/scripts/`)
- Страницы без og-тегов / title

### 3. Сводка
```
HIGH:   <N> (404-ассеты, битые ссылки, пустые partials)
MEDIUM: <N> (рассинхрон локалей, разные ?v=, без og-тегов)
LOW:    <N> (мёртвый CSS, дубли, копипаста)
```
Для каждой HIGH — файл, строка, что не так.
